## 目標
收尾：確保六大功能整體品質沒問題、留下完整文件方便之後維護，並讓既有的 LINE 推播機制跟上新的排行資料範圍。

## 範圍
包含：

### QA
1. 端對端檢查六大功能：三種殖利率排行、除權息日程表、合理價試算、風險試算，逐一在正式上線的網址上操作一次。
2. 資料正確性抽查：挑 5–10 檔涵蓋不同情境的股票（高殖利率、低殖利率、上櫃、ETF、新上市資料不足）過一遍所有功能，確認顯示合理、沒有明顯錯誤或當機。
3. 錯誤情境檢查：資料檔案缺失、API 暫時失效時，前端與排程分別會怎麼表現（不應該讓使用者看到一片空白或 JS 錯誤訊息）。
4. 跨瀏覽器基本檢查（Chrome、手機 Safari/Chrome 至少各測一次）。

### 文件
1. 更新根目錄 `README.md`：專案介紹、六大功能說明、資料夾結構、如何在本機開發、資料來源與更新頻率、已知限制（例如上櫃股票哪些功能受限、風險試算的定義依據）。
2. 簡單的維運手冊：GitHub Actions 排程失敗時要怎麼排查、怎麼手動重跑資料更新、怎麼在本機測試改動。

### LINE 推播更新（沿用既有 `line_push.py` 機制）
1. 擴充 `build_message()`：目前只推「當年殖利率排行 Top 5」，可以視需要加入 5年/10年榜重點，或除權息日程提醒（例如「本週有 N 檔股票即將除息」）。
2. 確認 `run_daily_push.ps1` 或改成 GitHub Actions 觸發（跟任務 07 的自動化排程整合，取代目前依賴本機排程器的方式）。

不包含：
- 新增功能本身（這個任務是收尾/驗證，不是開發新東西）
