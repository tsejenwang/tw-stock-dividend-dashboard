## 目標
讓整個網站能透過網址，在手機、平板、其他電腦等不同裝置上遠端瀏覽到完整、資料每日自動更新的內容。

## 範圍
包含：
1. **在實際操作前，先跟需求方確認**：
   - 要推送到哪一個 GitHub 帳號／建立哪個 repo（新 repo，還是既有帳號下的專案）
   - repo 要設 public 還是 private（GitHub Pages 免費方案通常需要 public repo，除非有 GitHub Pro/Team）
   - 是否需要自訂網域，或用 GitHub 預設的 `*.github.io` 網址即可
2. 確認完成後：
   - 把本機 git repo（任務 01 建立的）推到 GitHub
   - 開啟 GitHub Pages 設定，指向正確的分支/資料夾
   - 確認任務 07 的 GitHub Actions workflow 在 GitHub 上能正常觸發（不只是本機語法檢查）
3. 跨裝置驗證：
   - 用手機瀏覽器（行動網路，不是同一個 Wi-Fi，確保是真的「遠端」而不是區網存取）打開網址，檢查六大功能頁面都能正常顯示
   - 用平板／另一台電腦重複檢查
   - 檢查 HTTPS 是否正常（GitHub Pages 預設會提供）
4. 效能檢查：頁面載入速度、JSON 檔案大小是否過大（如果全市場清單很大，考慮是否要分檔案或做基本的資料精簡，只放前端實際會用到的欄位）。

不包含：
- 自訂網域的 DNS 設定細節（如果需要自訂網域，這部分要另外處理，因為涉及使用者自己的網域資源）
- 使用者帳號系統、權限控管（目前範圍是公開瀏覽，沒有登入需求）

## 驗收標準
- [ ] 已跟需求方確認並取得 GitHub repo 相關設定的同意
- [ ] 網址能在非本機網路環境（例如手機行動網路）成功開啟
- [ ] 六大功能頁面在手機瀏覽器上都能正常顯示與操作
- [ ] GitHub Actions 排程有成功執行至少一次，且更新後的資料有反映到網站上
- [ ] 記錄下最終網址，更新進根目錄 `README.md`

## 技術備註
- 這個任務涉及「建立外部帳號/服務串接」與「推送程式碼到公開可見的地方」，屬於需要事先確認、不能自動執行的動作類別。
